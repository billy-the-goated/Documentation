Jellyfin on Arch Linux

Install the server, connect your drives, and reach it from outside your home network.

Step 1: Install Jellyfin, start it, and log in on localhost

Update, then install

Jellyfin is in the official repos. You need the server, the web client, and jellyfin-ffmpeg for transcoding.

sudo pacman -Syu
sudo pacman -S jellyfin-server jellyfin-web jellyfin-ffmpeg

Start it and enable it on boot

sudo systemctl enable --now jellyfin
systemctl status jellyfin

You should see active (running). If not, read the logs with journalctl -u jellyfin -e.

Open it on localhost

In a browser on the server, go to http://localhost:8096.

First-time setup wizard

  1. Pick your display language.
  2. Create your admin username and a strong password.
  3. Skip adding a library for now (Step 2 covers it).
  4. Choose the metadata language and country.
  5. Keep "Allow remote connections to this server" ticked. You need it for Step 3.
  6. Finish and log in.

Test from another device (optional)

ip a

Find your 192.168.x.x address, then open http://192.168.x.x:8096 from another device on the same network. If it doesn't load and you use ufw:

sudo ufw allow 8096/tcp

Step 2: Point Jellyfin at an external drive

Before you start: is your drive already ext4?

Plug the drive in and check its filesystem:

lsblk -f

Look at the FSTYPE column for your partition (for example sdb1).

Already ext4, with data you want to keep

Do not format it. Formatting erases everything. Skip the format step in 2.1.

  1. Note the partition name and its UUID from lsblk -f.
  2. Go to "Get the drive's UUID" in 2.1, then mount it and add it to fstab.
  3. Fix ownership so Jellyfin can read your existing files (this can take a few minutes on a big drive): 
    sudo chown -R jellyfin:jellyfin /mnt/media
  4. Optional: add a label. This doesn't touch your data and the UUID stays the same. 
    sudo e2label /dev/sdb1 media
  5. Check your folders against the layout in "Organise your files". Other structures still work as libraries, but this one matches best.

ext4, but you want to start fresh

Format it as shown in 2.1. Back up anything you need first.

Blank, or NTFS / exFAT / FAT32

Follow 2.1 from the top, including the format step. ext4 is strongly recommended because it handles Linux permissions properly. Copy any files you want to keep to another disk first.

2.1 One drive

Find the drive

lsblk

Match it by size. External drives are usually sdb, sdc and so on. Use the partition (sdb1), not the whole disk (sdb).

Format it (new or disposable drives only)

This erases the drive. Double-check the device name. Skip this if the drive is already ext4 with data you want.

sudo mkfs.ext4 -L media /dev/sdb1

Formatting creates a new UUID, so always get the UUID after formatting.

Get the drive's UUID

Always mount by UUID, because /dev/sdX names can change between reboots.

Method 1: lsblk -f

NAME   FSTYPE LABEL  UUID                                 MOUNTPOINTS
sda
├─sda1 vfat          1A2B-3C4D                            /boot
└─sda2 ext4          f1e2d3c4-b5a6-7890-abcd-ef1234567890 /
sdb
└─sdb1 ext4   media  9a8b7c6d-5e4f-3a2b-1c0d-e9f8a7b6c5d4

The long string in the UUID column is what you need.

Method 2: blkid

sudo blkid /dev/sdb1
/dev/sdb1: LABEL="media" UUID="9a8b7c6d-5e4f-3a2b-1c0d-e9f8a7b6c5d4" TYPE="ext4"

Copy the UUID, not the PARTUUID. fstab needs the filesystem UUID.

Create the mount point and mount it

sudo mkdir -p /mnt/media
sudo mount /dev/sdb1 /mnt/media

Mount on boot

Append the line directly to avoid UUID typos (change /dev/sdb1 to your partition):

echo "UUID=$(sudo blkid -s UUID -o value /dev/sdb1)  /mnt/media  ext4  defaults,nofail  0  2" | sudo tee -a /etc/fstab

Or edit by hand with sudo nano /etc/fstab and add:

UUID=your-uuid-here  /mnt/media  ext4  defaults,nofail  0  2

nofail lets the server boot even if the drive is unplugged. Check the result, then test without rebooting:

tail -n 3 /etc/fstab
sudo systemctl daemon-reload
sudo umount /mnt/media
sudo mount -a
df -h /mnt/media

If df shows the drive at /mnt/media, fstab works.

Give Jellyfin permission

sudo chown -R jellyfin:jellyfin /mnt/media
sudo -u jellyfin ls /mnt/media

Organise your files

/mnt/media/
├── Movies/
│   └── Movie Name (2020)/
│       └── Movie Name (2020).mkv
└── Shows/
    └── Show Name/
        └── Season 01/
            └── Show Name S01E01.mkv

Add it to Jellyfin

  1. Open http://localhost:8096 and log in.
  2. Go to Dashboard → Libraries → Add Media Library.
  3. Pick the content type (Movies or Shows) and click + next to Folders.
  4. Choose /mnt/media/Movies (or /mnt/media/Shows) and press OK.
  5. Repeat for each library and let Jellyfin scan.

2.2 Two or more drives with mergerfs

mergerfs combines several drives into one folder, so Jellyfin sees a single large library.

sudo pacman -S mergerfs

Prepare each drive

Repeat these steps from 2.1 for every drive, since each has its own UUID:

  1. Find the partition with lsblk.
  2. Check it with lsblk -f. If it's already ext4 with data you want, don't format it; mergerfs will include it as it is. If it's blank, format it with mkfs.ext4 and a different label for each (disk1, disk2).
  3. Get its UUID with lsblk -f or sudo blkid /dev/sdX1.
sudo mkdir -p /mnt/disk1 /mnt/disk2 /mnt/media

Add the drives to fstab

echo "UUID=$(sudo blkid -s UUID -o value /dev/sdb1)  /mnt/disk1  ext4  defaults,nofail  0  2" | sudo tee -a /etc/fstab
echo "UUID=$(sudo blkid -s UUID -o value /dev/sdc1)  /mnt/disk2  ext4  defaults,nofail  0  2" | sudo tee -a /etc/fstab

Add the merged mount

Add this below those lines:

/mnt/disk1:/mnt/disk2  /mnt/media  fuse.mergerfs  defaults,allow_other,use_ino,cache.files=off,dropcacheonclose=true,category.create=mfs,moveonenospc=true,minfreespace=50G,nofail  0  0
  • allow_other lets other users, like jellyfin, use the pool.
  • category.create=mfs writes new files to the drive with the most free space. Use epmfs to keep a show's files together on one drive.
  • moveonenospc=true moves a write to another drive if one fills up.
  • minfreespace=50G stops using a drive once it has less than 50 GB free.

Mount, test, set permissions

sudo systemctl daemon-reload
sudo mount -a
df -h /mnt/media
sudo chown -R jellyfin:jellyfin /mnt/disk1 /mnt/disk2

/mnt/media should show the combined size. Add libraries as in 2.1, always through /mnt/media, never the individual disks.

Make Jellyfin wait for the drives

This stops Jellyfin starting before the pool is mounted and seeing an empty library.

sudo systemctl edit jellyfin

Add this, save, then run sudo systemctl restart jellyfin:

[Unit]
RequiresMountsFor=/mnt/media

2.3 Backups with multiple drives

mergerfs is not a backup. If one drive dies, you lose what was on it.

Option A: a separate backup drive with rsync

Prepare a spare drive and mount it at /mnt/backup (same process as 2.1, including the UUID). It must be at least as big as all your media combined.

rsync -avh --progress /mnt/media/ /mnt/backup/media/

Leave out --delete, so an accidental delete won't wipe your backup. To run it weekly, create /etc/systemd/system/media-backup.service:

[Unit]
Description=Backup media library

[Service]
Type=oneshot
ExecStart=/usr/bin/rsync -avh /mnt/media/ /mnt/backup/media/

and /etc/systemd/system/media-backup.timer:

[Unit]
Description=Weekly media backup

[Timer]
OnCalendar=Sun 03:00
Persistent=true

[Install]
WantedBy=timers.target
sudo systemctl enable --now media-backup.timer

Option B: SnapRAID

SnapRAID keeps a parity drive that can rebuild a failed drive without a full second copy. It pairs well with mergerfs and suits libraries that rarely change. It's in the AUR as snapraid.

Back up Jellyfin's own data

Users, watch history and metadata live in /var/lib/jellyfin, and settings in /etc/jellyfin.

sudo rsync -avh /var/lib/jellyfin/ /mnt/backup/jellyfin-data/

Step 3: Port forwarding

Port forwarding tells your router to send internet traffic on a given port to your server. Jellyfin uses TCP 8096. You need the server's local IP, the router's IP, and your public IP.

3.1 Find the server's local IP

ip -4 a

Find your active interface (enp3s0, wlan0 and so on) and its inet line:

inet 192.168.1.50/24 brd 192.168.1.255 scope global dynamic enp3s0

The local IP here is 192.168.1.50. Ignore 127.0.0.1. A shortcut:

ip route get 1.1.1.1 | awk '{print $7; exit}'

3.2 Make the local IP permanent

If the server's IP changes after a reboot, the port forward points at nothing and stops working.

Option A: DHCP reservation on the router (recommended)

Find DHCP Reservation, Static DHCP or Address Reservation in the router settings. Pick your server, or enter its MAC address (the link/ether value from ip link), and assign it an IP.

Option B: static IP on the server (NetworkManager)

nmcli con show
sudo nmcli con mod "Wired connection 1" ipv4.method manual ipv4.addresses 192.168.1.50/24 ipv4.gateway 192.168.1.1 ipv4.dns "1.1.1.1,8.8.8.8"
sudo nmcli con up "Wired connection 1"

Pick an address outside your router's DHCP range. Use ethernet rather than Wi-Fi for a server if you can.

3.3 Find the router's IP

ip route | grep default

If it shows default via 192.168.1.1, open http://192.168.1.1 and log in. The admin password is often on a sticker on the router.

3.4 Create the port forward

Look for Port Forwarding, NAT, Virtual Server or Applications & Gaming, then create a rule:

FieldValue
NameJellyfin
ProtocolTCP
External / WAN port8096
Internal / LAN port8096
Internal IPYour server's local IP (for example 192.168.1.50)
EnabledYes

Save and apply. Some routers need a reboot. Forward only TCP 8096; the discovery ports (1900/udp, 7359/udp) are for your local network only.

3.5 Server firewall

If you use ufw (otherwise skip):

sudo ufw allow 8096/tcp
sudo ufw status

3.6 Find your public IP and check for CGNAT

curl ifconfig.me

This is the address people outside use to reach you. Compare it with the WAN / Internet IP on your router's status page.

If they differ, or the router shows an address starting 100.64. to 100.127., 10. or 192.168., your ISP uses CGNAT and port forwarding cannot work.

Your options are to ask the ISP for a public IP, or to use a tunnel. Tailscale is the easiest and safest for Jellyfin. Cloudflare's free tunnel restricts streaming video, so avoid it for this.

3.7 Test it

  1. Turn off Wi-Fi on your phone so it uses mobile data. Testing from inside your own network often fails even when everything is right.
  2. Open http://YOUR_PUBLIC_IP:8096. You should see the Jellyfin login page.

You can also use an online open-port checker with your public IP and port 8096.

3.8 Jellyfin network settings

In Dashboard → Networking:

  • "Allow remote connections to this server" is ticked.
  • Local HTTP port number is 8096.
  • Automatic port mapping (UPnP) is off. It's a security risk and you've set the forward by hand.

3.9 Keep it secure

  • Use strong, unique passwords on every account, especially the admin.
  • Give admin rights only where needed.
  • Keep Jellyfin updated with sudo pacman -Syu.
  • Plain HTTP on 8096 sends passwords unencrypted. For more than casual use, put a reverse proxy such as Caddy or nginx in front with a free HTTPS certificate, forward ports 80 and 443 instead, and close 8096 to the outside.
  • Back up your Jellyfin data (see 2.3).

3.10 When your public IP changes

Most home connections have a dynamic public IP that changes after a router restart or at the ISP's whim. A Dynamic DNS service such as DuckDNS (free) gives you a fixed name like myserver.duckdns.org that follows your IP.
