Arch Linux with archinstall and i3

A minimal install, then a lightweight i3 desktop with sound, wallpaper, brightness keys, a login screen, and the AUR.

Step 1: Install Arch with archinstall

Make the install USB

Download the ISO from https://archlinux.org/download and check its checksum against the one on that page:

sha256sum archlinux-x86_64.iso

Find your USB stick, then write the ISO to it.

lsblk
sudo dd if=archlinux-x86_64.iso of=/dev/sdX bs=4M status=progress oflag=sync

Replace /dev/sdX with the whole USB device (like /dev/sdb, not sdb1). The wrong device means erasing the wrong disk.

Boot it and get online

Boot from the USB (usually F12, F2 or Esc at power-on). You land in a root shell. Check that you booted in UEFI mode (the command should list files):

ls /sys/firmware/efi

Ethernet connects by itself. For Wi-Fi:

iwctl
station wlan0 scan
station wlan0 get-networks
station wlan0 connect "YourNetworkName"
exit
ping -c 3 archlinux.org

Run archinstall

archinstall

Go through the menu. Move with the arrow keys, pick with Enter. The options can sit in slightly different places between versions.

Select Install. When it finishes, answer No to "chroot into the new installation", then reboot and unplug the USB:

reboot

Step 2: First boot

You get a text login. Log in as the user you created (not root). Check the network:

ping -c 3 archlinux.org

If you're on Wi-Fi, connect with the text interface:

nmtui

Choose "Activate a connection", pick your network, and enter the password. Then update everything:

sudo pacman -Syu

If you skipped adding extras in archinstall, install them now:

sudo pacman -S --needed git base-devel nano

Step 3: Install i3, dmenu and their dependencies

A minimal install has no graphical system, so you need the display server (Xorg), the window manager, the launcher, a terminal and fonts.

sudo pacman -S xorg-server xorg-xinit xorg-xrandr xorg-xev i3-wm i3status i3lock dmenu xterm ttf-dejavu
  • xorg-server and xorg-xinit are the display server and startx.
  • xorg-xrandr sets screen resolution and monitors. xorg-xev shows key names (used in Step 8).
  • i3-wm is the window manager. i3status is the status bar content. i3lock locks the screen.
  • dmenu is the app launcher. Pacman pulls in its library dependencies automatically.
  • xterm is a small terminal (swap for alacritty or kitty if you prefer). ttf-dejavu gives you readable fonts.

Graphics drivers

The Minimal profile doesn't install them, so add the right one for your hardware:

GraphicsInstall
Intel or AMDsudo pacman -S mesa
NVIDIAsudo pacman -S nvidia-open nvidia-utils (older cards: see the Arch wiki NVIDIA page)

Step 4: Install Ly and enable ly@tty2

Ly is a small text-mode login screen. It starts i3 for you, so you never need startx. It needs the i3 session and graphics driver from Step 3, so do that step first.

sudo pacman -S ly

Ly runs on tty2, so turn off the normal login on that terminal and enable Ly there:

sudo systemctl disable getty@tty2.service
sudo systemctl enable ly@tty2.service

Reboot:

reboot

At the Ly screen, press the left/right arrow keys to choose the i3 session, enter your username and password, and press Enter. The i3 session entry comes with the i3-wm package. The first time i3 starts, it asks to create a config, which Step 5 covers. Settings live in /etc/ly/config.ini.

If Ly doesn't appear, you can still get a text login on tty1 with Ctrl+Alt+F1. Then check the service with systemctl status ly@tty2.service.

To go back to a plain text login on tty2 later, reverse it:

sudo systemctl disable ly@tty2.service
sudo systemctl enable getty@tty2.service

Step 5: First login and the i3 config

Log in through Ly with the i3 session selected (Step 4). On the first launch i3 asks to create a config. Press Enter to generate it, then pick your modifier key: Win (Super) is the usual choice. The config lives at:

~/.config/i3/config

If the wizard doesn't appear, copy the default instead:

mkdir -p ~/.config/i3
cp /etc/i3/config ~/.config/i3/config

Basic keys

With Win as the modifier ($mod):

  • $mod+Enter opens a terminal.
  • $mod+d opens dmenu to launch apps.
  • $mod+Shift+q closes the focused window.
  • $mod+1 to $mod+9 switch workspaces. $mod+Shift+1 to 9 move a window there.
  • $mod+Shift+r reloads the config. $mod+Shift+e exits i3.

Edit the config from an i3 terminal with nano ~/.config/i3/config, save, then press $mod+Shift+r. To pick the modifier by hand, find this line (Mod4 is Win, Mod1 is Alt):

set $mod Mod4

The default config starts a few extra programs (dex, xss-lock, nm-applet) that a minimal install doesn't have. They cause harmless errors. Either put a # in front of those exec lines, or install them with sudo pacman -S dex xss-lock network-manager-applet.

Leave i3 safely

Press $mod+Shift+e and confirm. You return to the text login.

Step 6: Audio and the aux (headphone) port

Install the audio stack

If you picked pipewire in archinstall, most of this is installed already. Running it again is harmless:

sudo pacman -S --needed pipewire pipewire-pulse pipewire-alsa wireplumber alsa-utils pavucontrol

Make sure the audio services start for your user:

systemctl --user enable --now pipewire.socket pipewire-pulse.socket wireplumber.service

Check that a sound card exists

wpctl status

You should see your card under "Audio → Sinks". If nothing shows up, install the firmware that newer laptops need, then reboot:

sudo pacman -S sof-firmware
reboot

Unmute the channels

ALSA channels are often muted by default. Open the mixer:

alsamixer

Press F6 to pick your sound card. A channel showing MM is muted, so select it and press M to unmute it (it changes to 00). Check Master, Headphone and Speaker. Raise volumes with the up arrow. Then save the state so it survives a reboot:

sudo alsactl store

Test sound

speaker-test -c 2 -t wav

Press Ctrl+C to stop. You should hear a voice alternate between left and right.

Make the aux port work with an exec command

Plug in headphones (or a speaker on the 3.5 mm jack) and list the output ports:

pactl list sinks | grep -E "Name:|Active Port|analog-output"

You'll see port names like analog-output-speaker and analog-output-headphones. Test switching by hand:

pactl set-sink-port @DEFAULT_SINK@ analog-output-headphones

If that works, make i3 run it at every start. Add these lines to ~/.config/i3/config:

# Audio: unmute and use the aux/headphone port
exec --no-startup-id amixer sset Master unmute
exec --no-startup-id amixer sset Headphone unmute
exec --no-startup-id pactl set-sink-port @DEFAULT_SINK@ analog-output-headphones

WirePlumber normally switches to the headphone port by itself when you plug in. The pactl line is only needed if yours doesn't. If you force it, the laptop speakers stay silent even when the headphones are unplugged. Delete that line if you'd rather it switch automatically. If a mixer control name (like Headphone) doesn't exist on your hardware, that line just fails without harm.

Volume keys

Add these so the keyboard volume keys work (replace any existing XF86Audio lines):

bindsym XF86AudioRaiseVolume exec --no-startup-id wpctl set-volume -l 1.0 @DEFAULT_AUDIO_SINK@ 5%+
bindsym XF86AudioLowerVolume exec --no-startup-id wpctl set-volume @DEFAULT_AUDIO_SINK@ 5%-
bindsym XF86AudioMute exec --no-startup-id wpctl set-mute @DEFAULT_AUDIO_SINK@ toggle

Reload with $mod+Shift+r. pavucontrol gives you a graphical mixer if you want to check which output is selected.

Step 7: Set a wallpaper with feh

sudo pacman -S feh

Put an image somewhere permanent, such as ~/Pictures/wallpaper.jpg:

mkdir -p ~/Pictures

Test it from a terminal inside i3:

feh --bg-fill ~/Pictures/wallpaper.jpg

Then make i3 set it at every start by adding this to ~/.config/i3/config:

exec --no-startup-id feh --bg-fill ~/Pictures/wallpaper.jpg

--bg-fill scales the image to fill the screen and crops the overflow. Other modes are --bg-center, --bg-scale (stretches), --bg-max (fits with borders) and --bg-tile. Use exec_always instead of exec if you want the wallpaper to be reapplied every time you reload the config, not just at login.

Step 8: Brightness keys with brightnessctl

sudo pacman -S brightnessctl

Give your user permission

Without this you get permission errors. Add yourself to the video group, then log out of i3 ($mod+Shift+e) and log back in through Ly:

sudo usermod -aG video $USER

Test it

brightnessctl info
brightnessctl set 10%+
brightnessctl set 10%-

Bind it to your keys

Add these to ~/.config/i3/config:

bindsym XF86MonBrightnessUp exec --no-startup-id brightnessctl set 5%+
bindsym XF86MonBrightnessDown exec --no-startup-id brightnessctl set 5%-

Reload with $mod+Shift+r. If pressing the keys does nothing, find out what your keyboard sends. Run xev -event keyboard, press the key, and look for the XF86... name in the output (Ctrl+C to quit). Then use that name in bindsym. If your keyboard has no brightness keys, bind regular ones:

bindsym $mod+F6 exec --no-startup-id brightnessctl set 5%-
bindsym $mod+F7 exec --no-startup-id brightnessctl set 5%+

On some panels, brightness at 0% turns the screen fully black. If that happens, press the up key to bring it back.

Step 9: Install yay (AUR helper)

yay installs packages from the Arch User Repository (AUR), which pacman can't reach. It needs git and base-devel (skip this line if you added them earlier):

sudo pacman -S --needed git base-devel

Build and install it. Do not run this as root or with sudo, because makepkg refuses to.

git clone https://aur.archlinux.org/yay.git ~/yay
cd ~/yay
makepkg -si

If you'd rather not compile it, yay-bin from the same site installs faster. Use the same three commands with yay-bin.git. Check it worked and clean up:

yay --version
cd ~
rm -rf ~/yay

Everyday use

yay -S package-name    # install from the repos or AUR
yay -Syu               # update everything, AUR included
yay -Ss search-term    # search
yay -Rns package-name  # remove a package and its unused dependencies

AUR packages are written by users, not checked by the Arch team. Read the PKGBUILD when yay offers to show it, and only install packages you trust.

Troubleshooting

ProblemLikely cause
Black screen or "no screens found" when i3 startsMissing graphics driver (Step 3). Check ~/.local/share/xorg/Xorg.0.log.
No sound at allMuted in alsamixer, or missing sof-firmware. Also check wpctl status to see if a sink exists.
Sound from speakers but not the aux portWrong sink port. Run the pactl list sinks command in Step 6 and use the port name it shows.
Sound is fine in the terminal but exec lines do nothingReload i3 with $mod+Shift+r. Exec lines run once at login, not on reload (unless you use exec_always).
Wallpaper is blackWrong image path in the config, or the file isn't readable. Run the feh command by hand to see the error.
brightnessctl says permission deniedNot in the video group, or you haven't logged out and back in since adding yourself
Brightness keys do nothingYour keyboard sends a different key name. Check with xev -event keyboard.
Want to test i3 without LyLog in on tty1 (Ctrl+Alt+F1), then run echo "exec i3" > ~/.xinitrc and startx
Ly doesn't show up after rebootThe service isn't enabled, or getty@tty2 is still running. Check systemctl status ly@tty2.service.
makepkg says it can't run as rootRun it as your normal user, without sudo
No Wi-Fi after installNetworkManager wasn't selected in archinstall. Run sudo pacman -S networkmanager and sudo systemctl enable --now NetworkManager.
